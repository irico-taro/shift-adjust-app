# シフト管理アプリ (MVP)

「レッスン枠」(資格マッチングが必要な固定コマ)と「業務シフト」(時間帯勤務)が混在する
ハイブリッド型のシフト管理アプリです。要件定義のデータモデルをそのまま実装し、
**希望収集 → 管理者による調整 → 確定** のワークフローで運用します。

技術スタック: **Next.js 15 (App Router) / React 19 / TypeScript / SQLite (better-sqlite3)**

## セットアップ

必要環境: **Node.js 22 または 24**(`node -v` で確認)。
SQLite ドライバのビルド済みバイナリが配布されているため、Python や C++ ビルドツールは不要です。

```bash
npm install
npm run dev      # http://localhost:3000
```

初回起動時に `data/shift.db` が作られ、動作確認用のサンプルデータ
(ヨガスタジオ想定: スタッフ6名・レッスン種別3件・曜日テンプレート37枠・当月の期間と希望シフト)
が自動投入されます。作り直したいときは:

```bash
npm run db:reset   # data/shift.db を削除。次回起動時に再投入される
```

その他のコマンド:

```bash
npm test         # ルール判定・自動割当のテスト
npm run build    # 本番ビルド
npm run typecheck
```

## 画面

| パス | 画面 | 内容 |
|---|---|---|
| `/` | 期間一覧 | 期間の作成、フェーズ・充足率・違反件数の一覧 |
| `/periods/[id]` | シフト表(メイン) | 日付×枠のマトリクス。自動生成・手動調整・警告表示 |
| `/periods/[id]/availability` | 希望入力 | スタッフごとに日付単位で ok / ng / conditional を入力 |
| `/staff` | スタッフ管理 | 資格(担当可能レッスン)・週労働時間の上下限 |
| `/template` | 曜日テンプレート | レッスン種別と、曜日ごとの枠・必要人数 |
| `/rules` | 労働ルール | テンプレートから選んで数値を設定 |

### シフト表の操作

- セルの **「+」** で候補スタッフ一覧を開く。各候補には「なぜ割り当てられない/注意が必要か」を並べて表示し、
  違反があっても管理者の判断で強制割当できます(割当後は警告として残ります)。
- 名前チップの **クリックで解除**。
- **枠ごと / スタッフごと** を切り替えると、同じデータをレッスン枠と業務シフトを統合した
  1人のタイムラインとして確認できます。
- **赤セル** = 人手不足またはルール違反、**黄セル** = 必要人数超過・条件付き希望。
- 変更は即座に SQLite へ保存され、ルール判定はクライアント側で再計算されるため警告がリアルタイムに更新されます。

| 要件定義 | テーブル | 補足 |

## ルールエンジン

要件定義 4. の「**自動生成用ロジックとバリデーション用ロジックは共通化する**」に従い、
判定は `src/lib/rules.ts` の純粋関数に集約しています。サーバー(自動生成)とクライアント
(リアルタイム警告)が同じ関数を呼ぶため、生成結果と画面の警告が食い違いません。

- `violationsForAssignment()` — 1件の割当が抱える違反。既存割当の検証にも、
  「この人をここに入れられるか」の候補判定にも同じ関数を使う。
- `evaluateSchedule()` — 期間全体を検証し、セル別・割当別・スタッフ別に違反をまとめる。
- `violationsIfAssigned()` — 仮に割り当てた場合の違反(候補一覧の表示に使用)。

判定内容:

| 種類 | レベル | 説明 |
|---|---|---|
| 資格 | エラー | レッスン枠に `qualifiedLessonTypeIds` を満たさない人 |
| 希望 NG | エラー | 終日 NG の日への割当 |
| 条件付き希望 | エラー | 申告した可能時間帯から外れる枠 |
| 希望未提出 | 注意 | その日の希望が未入力 |
| 勤務の重なり | エラー | 同一スタッフの勤務時間が重複 |
| minInterval | エラー | 特定勤務の後、次の勤務まで最低◯時間 |
| forbiddenSequence | エラー | 例:夜勤の翌日は早番不可 |
| maxConsecutiveDays | エラー | 連勤上限 |
| weeklyHoursRange | エラー/注意 | 週労働時間の上限超過(エラー)・下限未達(注意) |
| requiredCount 過不足 | 注意 | 人手不足・必要人数超過 |

日跨ぎ勤務(例: 夜勤 22:00〜06:00)は終了時刻が開始時刻以下の枠として扱い、
インターバルや重なりの判定は期間先頭を基準にした通算分で比較します。
週の区切りは月曜始まりで、下限チェックは期間に完全に含まれる週だけを対象にします。

## 自動割当(たたき台生成)

`src/lib/autoAssign.ts`。完全自動最適化ではなく「叩き台を作って人が直す」方針です。

1. 前日の勤務を見ないとルール判定できないため、**日付順に逐次処理**。
2. 各日で **資格を満たす人が少ないコマから**確定させる。
3. 候補はエラーレベルの違反が出ない人だけに絞り、
   **希望を尊重(ok > conditional > 未提出)→ 注意の少なさ → 労働時間・担当コマ数の均等** の順で選ぶ。
4. 埋められないコマは不足として報告し、画面上で赤セルになる。

`confirmed` の割当は作り直しても保持されます。「不足分だけ埋める」は既存の割当を残したまま
不足しているコマだけを補います。

## テスト

`tests/rules.test.ts` に18件。DB を使わず、手で組んだデータで純粋関数の振る舞いを検証します
(日跨ぎ勤務の時間計算、各ルールの検出、たたき台がエラーレベルの違反を作らないこと、
希望 NG の人を割り当てないこと、など)。

## うまくいかないときは

**`npm install` が `gyp ERR! find Python` で失敗する**

`better-sqlite3` がお使いの Node.js 用のビルド済みバイナリを見つけられず、自前ビルドに切り替わった状態です。
まず `node -v` を確認してください。Node 20 以下、または 25 以降の場合はビルド済みバイナリが無いため、
**Node.js 22 か 24** に入れ替えるのが確実です(Python の導入は不要)。

失敗した `node_modules` が中途半端に残っていると次のインストールも失敗するので、
入れ替え後はフォルダごと消してからやり直してください。

```bash
# Windows (PowerShell)
Remove-Item -Recurse -Force node_modules
npm install
```

**ポート 3000 が使用中と言われる / 別のポートで起動する**

起動時のログに出た `Local:` の URL を開いてください。任意のポートを指定するには `PORT=3001 npm run dev`
(PowerShell では `$env:PORT=3001; npm run dev`)。
